# BiliPlayer

一个跑在自己电脑上的 B 站订阅播放器。不嵌网页、不装插件，读你自己的关注列表，
按内容分类摆成封面卡片，点开就在本地窗口里播——带弹幕、能看评论、能改倍速和清晰度。

做它的原因很直接：B 站自己的动态页，关注了不一定会推、分了组还是混在一起、
搬运号和自家推广挤在一屏、停更半年的人沉到看不见。想看的东西明明就在那儿，就是翻不到。

它只做"看"这件事，而且只在这台机器上跑：服务只监听 `127.0.0.1`，
除了 B 站自己的接口，不往外发任何东西。

---

## 拿到手怎么用

需要 Python 3.8 以上，没有别的依赖（视频播放器 dash.js 已经放在 `static/` 里了）。

**Windows**：解压后双击 `启动BiliPlayer.bat`。它会自己在这个电脑上找 Python
（PATH 里的 `pythonw`、`py` 启动器、`Program Files` 下的各个 3.x 都试一遍），
只要装了就能起来，没装会提示去装。第一次会让你填一串东西（见下面「第一次配置」），
之后每次双击就是秒开。

**macOS**：双击 `BiliPlayer.command`（在终端里会跑起来，窗口别关）。或者 `./start.sh`。

**Linux**：`./start.sh`，或者 `python3 launch.py`。

三个入口做的事一样：先看本地服务在不在，不在就拉起来，然后自己找 Edge / Chrome /
Chromium / Brave 开一个应用窗口，都找不到就用默认浏览器。

窗口关掉后后台服务还在跑，再打开是秒开。想彻底停掉：Windows 在任务管理器里结束
`pythonw.exe`；macOS/Linux 里 `pkill -f server.py`。应用里左下角「退出」也会关掉服务。

### 第一次配置

程序需要知道"你是谁"，才能读到你的关注列表。这一步只要做一次。

1. 浏览器里登录 [bilibili.com](https://www.bilibili.com)
2. 按 `F12`，切到 **Application**（应用）标签
3. 左边 **Storage → Cookies → https://www.bilibili.com**
4. 找到 **SESSDATA**，双击 Value 那一格，全选复制
5. 粘进程序打开的页面里，点「连接并读取关注」

接下来它会去读你的关注列表和最近的动态，第一次要几分钟（几百个 UP 的话），
进度就显示在那个页面上。读完不会马上结束——它还要顺手把分类和推荐池算出来
（进度写着「正在归类」），这几步也各要一会儿。等都跑完，侧栏才会出现你的分类。

那串 SESSDATA 只写进本目录的 `config.json`，跟这个程序放在一起，不会上传到别处。
它等价于你的登录态，所以**别把这个文件发出去**——打包脚本已经自动排除了它。
想换账号：访问 `http://127.0.0.1:8791/setup` 重新填一次。

## 界面

左侧是内容分类，点哪个就只剩哪个，不混。数字是这一类的关注人数。

**"生活"和"影像·音乐"点开有二级标签。** 这两类人最多，从做饭到旅行、从翻唱到剧集解说
都有，一个大标签塞不住。生活分六支（吃·厨房、手作·维修、摄影·绘画、穿戴·身型、
出门·见闻、日常·闲聊），影像分五支（影视·解说、动画·番剧、音乐·演奏、译制·搬运、
鬼畜·整活）。选中就把它下面铺开，点某支只剩这一支，点"全部"回到整类。别的分类没有二级，
因为它们本来就没超过六七十人，而且边界清楚（历史就是历史）。每一支按什么判，
见下面「分类是怎么来的」。

最底下那个**待定**不是内容分类，是"看不出是什么"的那拨人——既没有近期投稿，
签名也是空的。放在这儿是为了让你能点进去手动定，而不是混在生活里冒充生活内容。

- **首页**：一打开就是这个。最上面写着这 24 小时有多少人发了几条；接着是**接着看**，
  看了一半没看完的都在这儿；再往下每个分类占一行，写着本周几个人有更新，行内是这一类
  最新的六条，右边「看全部」跳进这个分类；最底下是**关注之外**——全站热门里排掉你关注的人。
- **最新**：封面卡片流，按时间倒序。同一个 UP 默认最多占 2 张，多出来的折成一张
  「还有 N 条」的卡，点一下把这个人全放出来。右上角能改成 1/3/5 条或不限。
- **按人看**：一人一张头像卡，写着最近一条是什么、多久没更新、库里几条。
  名字下面那个灰色小标签是它现在归的类，点一下就能改——分错的人不用再改代码。
  右上角可以切成「最久没更新」，停更的人就浮到前面来了。
  卡片点进去是这个人的主页（下面「一个人的全部投稿」）。
- **看过**：播放记录，按最近看的排，写着「看到 12:34」，点开接着播。

每个分类顶上还有一条**延伸推荐**——这一类里你还没关注的人在发什么，点开就能播。
「换一批」换一组。这些是从分区热门里挑的，已经排掉你关注的和库里已有的。

搜索框搜的是你自己库里。**搜不到时会给你一个「在 B 站全站搜」的按钮**，
点了就换到全站搜索结果，看完点「回到关注」回来。

## 一个人的全部投稿

从「按人看」点任意一张卡片进去。首页那套卡片流只放最近几天的更新，停更的人
根本没有位置——这个页面就是为他们准备的。

顶上写着这个人归哪一类、库里多少条、最早一条是什么时候、最后更新是哪天。
下面是他的全部投稿，从新到旧，点开就播，播完自动接下一个。

右上角那个**「往前翻更早的投稿」**是关键：库里通常只有动态流抓到的最近一两条，
停更的人甚至是零条。点一下，它顺着这个人的空间动态一页页往回挖，一次大概五六十条，
按钮点几次就能翻到几年前。翻到哪记在库里（`ups.dyn_offset`），下次从那儿接着翻，
不会每次重头来。翻到最早一条时按钮自己变成「已经翻到最早一条了」。

**「按人看」顶上那条提示**：关注几百人、同步只往回翻 40 页动态，排在后面的人
一条都抓不到，所以会出现「还有 N 个人库里一条都没有」。旁边那个「补 80 个」是
挨个去他们空间各翻一页，把最近的投稿补进来。串行跑，一个人一次请求，进度就在
那条提示上，八十个人大概两分钟。补完这批再点还有下一批。

## 播放器

播的是正经 DASH 流，不是嵌 iframe，所以倍速、清晰度、弹幕都是自己的：

- **弹幕**：走老 XML 接口一次拉全片，自己用 canvas 画。滚动、顶部、底部三种都有，
  颜色字号照原样。右下角粉色「弹」按钮开关（`C`）。
- **评论**：右上角「评论」拉出侧栏，有热门评论、楼中楼、点赞数。能看不能发——
  发评论要写权限，这个程序不碰。
- **相关推荐**：同一个侧栏的第三个标签页，播完想接着看别的可以直接点。
- **进度条预览**：鼠标在进度条上滑，浮出那一刻的缩略图和时间。
- **分 P**：多 P 视频进度条上方多一个下拉。
- **连播**：播完接列表里的下一个，先给几秒反悔时间（秒数可设）。`⏮ ⏭` 手动切。
- **接着看**：进度每 5 秒存一次，下次打开自动跳回去。
- **顺手改分类**：播放器左上角标题下面写着 UP 名字和它现在归的类，点那个小标签就能改，
  分错了不用退出去找。
- **画面缩放**：上下有黑边的可以切「铺满」，但会切掉两边，看情况用。
- **画中画 / 截图 / 全屏**：`P` / `S`（存到下载文件夹）/ `F`，双击画面也是全屏。
- **在 B 站打开**：左上角那个按钮，或者鼠标放到封面上，右上角浮出的小箭头。
  点它用系统浏览器打开网页版——想在评论区说话、投币、收藏，去那边。

### 设置

播放器右下角齿轮。三页：

**播放**——画面缩放、默认清晰度、默认倍速、播完是否自动下一个、倒数几秒、
记忆播放位置、自动跳过片头（填秒数）、片尾提前结束（填秒数）、快进步长、滚轮调音量、双击全屏。

**弹幕**——显示开关、不透明度、字号、占用画面高度（越小越不挡脸，但同一时刻能显示的条数也少）、
滚动速度、加粗、描边粗细、滚动/顶部/底部三类分别开关、合并重复、屏蔽词（一行一个，支持简单正则）。

**快捷键**——一页列全，不用记。

设置存在 `data/settings.json`，换个窗口、换台机器拷过去都是同一套。

## 分类是怎么来的

不看 B 站原来的分组，按内容重新分。判断依据按可靠程度排：

**这个 UP 最近一条投稿挂在哪个分区** > 名字里的身份自述（"字幕组""讲史""博物馆"）>
已入库视频的标题 > 个性签名（先把"商务合作+v"这类句子切掉再用）。

分区是 UP 自己选的，最准；但机构号是例外——新华社被分到"日常"、半月谈被分到"财经商业"，
所以名字里能认出身份的机构号、出版社、博物馆，优先按身份判。

十个内容类：时政·社会 / 经济·商业 / 历史 / 思想·人文 / 科学·技术 / 读书·文学 /
影像·音乐 / 游戏 / 学习·课程 / 生活。原来"学校"分组里的人单独归到"同学·熟人"，
因为那是同学不是内容号，混在一起会干扰推荐。最后还有一个"待定"。

### 生活为什么拆成六支

原来它叫"生活·杂览"，一个人占 121 个（四分之一）。拆开看，里面混着讲巴西大选的、
讲日本失去的三十年的、玩十字军之王3 的、读苏童的——因为它的兜底逻辑是所有判不出来的
人都往这儿扔。现在：

- 大类还叫"生活"，点开后在侧栏展开六个小标签，各自的人数是分开算的。
- 兜底不再是"生活"，而是"待定"。这两个字是实话：这些人既没近期投稿、也没签名，
  看不出是什么，标出来比假装知道更有用。

六个分支，判据是名字、签名、最近几条标题里出现的关键词，越专指的越先匹配：

| 分支 | 收什么 | 认这些词 |
| --- | --- | --- |
| 吃·厨房 | 做饭、菜谱、探店、美食节目 | 美食、做饭、菜谱、厨房、厨艺、探店、干饭、烘焙、食材、舌尖 |
| 手作·维修 | 手工、DIY、修复、积木、居家妙招 | 手工、DIY、修复、翻新、积木、乐高、改造、收纳、木工、小妙招 |
| 摄影·绘画 | 拍照、风光、绘画、地图与地理影像 | 摄影、相机、构图、风光、绘画、水彩、素描、地理、地图 |
| 穿戴·身型 | 穿搭、美妆、健身 | 穿搭、美妆、化妆、护肤、健身、瑜伽、发型、球鞋 |
| 出门·见闻 | 旅行、旅居、异国观察 | 旅行、旅游、走遍、环球、见闻、异国、徒步、自驾 |
| 日常·闲聊 | vlog、生活记录、吐槽 | 日常、vlog、生活记录、随拍、杂谈、吐槽、整活 |

判不出具体哪一支、但确实是生活内容的，进"日常·闲聊"。顺序是刻意的：「厨房」这种词
只有做饭的人会用，所以排在「日常」前面——「书房连着厨房」这个名字会先落到吃·厨房，
虽然他的内容其实是苏童小说讲读（这种个案在 `MANUAL` 里单独钉正）。

除了这两个，还有"待定"这一类。它不收内容，收的是**信息不足**：翻过他的空间动态、
一条视频都没有，签名也是空的，那就不猜。

### 影像·音乐为什么拆成五支

它原来 98 个人，是拆分前最大的类，里面同时排着剧集解说、新番点评、二胡演奏、
字幕组和鬼畜。五支分下来，每支都能一句话说清：

| 分支 | 收什么 | 认这些词 |
| --- | --- | --- |
| 影视·解说 | 电影剧集的解说、深度解析、影评盘点 | 电影、影评、解说、精讲、一口气、看完、烂片、幕后、美剧英剧、影视 |
| 动画·番剧 | 新番点评、漫画解说、动画杂谈、音声与虚拟主播 | 番剧、新番、动漫、漫画、手书、音声、VUP、柯南、死神、辛普森 |
| 音乐·演奏 | 演奏、翻唱、乐评、音乐史 | 音乐、演奏、钢琴、二胡、吉他、翻唱、金曲、合唱、乐评、Lofi |
| 译制·搬运 | 字幕组、自译、中配、纪录片搬运 | 字幕组、中字、熟肉、自译、中配、译制、双语、搬运、纪录片 |
| 鬼畜·整活 | 鬼畜、搞笑剪辑、颜值合集 | 鬼畜、整活、恶搞 |

顺序上做了两处调整，都是试出来的：音乐排在影视前面——反过来的话，弹吉他的、做乐评的
会被标题里的"看完""一口气"抢走；「轻音」这个词从动画的判据里删掉了，它更常出现在
"轻音乐"里，一个人因此被误判成看番的。判不出细分、但确实是这一类的人落进影视·解说，
因为这一支本来就占了一半。

名字骗人的那批单独钉在 `MANUAL_SUB` 里，共 28 个。典型是音声剧和虚拟主播（名字里
一个相关字都没有）、以及自称"中字"其实在做自制动画的搬运号。

分类结果是推出来的，会有错。改起来三条路：

- **就地改**：在「按人看」里点卡片上那个灰色小标签，或者在播放器顶上点「分类：…」，
  弹层里选一个新类就改好了。选"生活"或"影像·音乐"的时候，下面会多一行细分让你直接
  选到具体分支。改过的人会在库里记一笔 `manual`，以后重跑分类不会再被冲掉；想反悔，
  同一个弹层里点「恢复自动分类」。
- **批量改**：改 `classify.py` 里的 `MANUAL`（大类）和 `MANUAL_SUB`（二级分支），
  跑一次 `python classify.py`。跑完末尾会打一段「体检」，列出"归在这一类、但最近六条
  标题看着像另一类"的人——人工表是某一刻的判断，人会换内容，这是唯一的发现办法。
- **给没线索的人补数据**：`python probe.py`，见下一节。

### 判不出来的时候先补数据，别硬猜

分类有四路信号：投稿分区、名字自述、标题关键词、签名。四路全空的人一般是几个月没投稿
的老关注——`enrich.py` 只抓最近一条投稿的分区，停更的人抓不到；签名又只有一串商务微信。

这时候跑 `python probe.py`：它顺着每个人的空间动态往回翻一页，把最近十几条投稿连标题
带封面写进库。补完之后标题就成了分类依据，这些人也才真正出现在时间线里。
实测 166 个人补进来 1369 条视频。

如果补完还是什么都看不出来（有的人确实一条投稿都没有），那就不判，进"待定"。

### 另外两个会拉偏分类的东西

**"日常"这个分区不能当依据。** B 站投稿页没选分区的话默认落在"日常"，讲投资的、
讲键政的、玩游戏的都有。以前 `classify.py` 把"日常"直接映射成生活，等于让二十个人在
完全不看内容的情况下定了终身。现在"日常""搞笑""出行""三农"这几个泛分区会被跳过，
继续往下看内容。

**两个字的通用词要降权。** "手机""历史""文学"这种词在标题里出现一次就能定类，可它们
在生活、影视、读书的标题里到处都是——光"手机"一个词就把四个人推进了科学·技术。
现在这些词（`WEAK` 表）权重减半，单独出现不够阈值。

## 数据从哪来

都用 B 站自己的 web 接口，没有第三方服务。

- **关注列表 + 分组**：`x/relation/tags`、`x/relation/tag`、`x/relation/followings`
- **视频**：关注动态流 `x/polymer/web-dynamic/v1/feed/all?type=video`，按时间倒序翻页。
  默认 40 页（约 8-10 天），`config.json` 的 `sync_pages` 可以加大，但 B 站只保留约 75 天。
- **某个人的全部历史投稿**：`x/polymer/web-dynamic/v1/feed/space?host_mid=`，按 `offset` 分页，
  能一直翻到这个人注册那天。
  这里更正一条以前的错误结论：以前记的是「UP 投稿列表接口全封，老的、wbi 签名的、
  空间动态流三条路都不通」。投稿列表 `x/space/arc/search` 确实还是封的（不带参数偶尔
  能过一页，加个 `order` 就 412；`x/space/wbi/arc/search` 签名算对了也照样 412，是冲着
  非浏览器 TLS 指纹来的），但**空间动态流 `feed/space` 一直通**，只是当时试错了地址。
  所以翻旧稿走的是动态流，不是投稿列表。
- **推荐池**：`x/web-interface/ranking/v2`（分区排行）+ `x/web-interface/popular`（综合热门），
  约两千条，缓存 6 小时，按分区名分到各分类并排除已关注的。
- **播放**：`x/player/playurl`。注意 `x/player/wbi/playurl` 对非浏览器的 TLS 指纹一律 412，
  只能用老接口。B 站 CDN 要求带 Referer，所以视频流全部走本地 `/stream` 中转；
  dash.js 要 MPD 而 B 站只给裸地址，所以现场按 SegmentBase 拼一份。
- **弹幕**：`x/v1/dm/list.so?oid=cid`，返回裸 deflate（`zlib.decompress(raw, -15)`），
  解出来是 `<d p="时间,模式,字号,颜色,...">文字</d>`。高级弹幕和代码弹幕不画。
  解析成 `[t, mode, color, text]` 存在 `data/dm/{cid}.json`，三天内不重复拉。
- **评论**：`x/v2/reply?type=1&oid={aid}&pn=&sort=`，不需要 wbi 签名。
- **进度条预览**：`x/player/videoshot`，给的是一张 10×10 的精灵图，按时间点取格子。
- **全站搜索**：`x/web-interface/search/type`，同样不需要签名。
- **图片**：封面和头像偶尔会被图床按 Referer 拦掉，所以内置了 `/api/img` 代理，
  只放行 `*.hdslb.com` 和 `*.bilibili.com`。

## 已知的限制

- **读书·文学这一类几乎推不出东西**。B 站没有读书分区，热门榜上几乎没有纯读书内容，
  按标题硬凑会捞出"送外卖供三姐弟读书"这种。宁可空着。
- **时政·社会推荐也少**。资讯区不上热门榜，只能从全站热门里按标题认（选举/议会/关税/加沙…）。
- **「最新」里只有最近约 75 天的投稿**，这是关注动态流本身的上限。想看更早的，
  进某个人的主页点「往前翻」——那条路没有 75 天的限制。
- 不能发评论、不能投币收藏、不能发弹幕——这些都要账号的写权限（`bili_jct`），
  这个程序只读不写。
- 1080P 以上（1080P+/4K/HDR/杜比）要大会员，接口给不了。有大会员的号能拿到 1080P60。
- 没有投屏。

## 打包给别人

```
python pack.py
```

产物在 `dist/BiliPlayer-<日期>.zip`。会自动排除 `config.json`（含登录凭据）、
`data/`（你的订阅库和播放记录）、`window_profile/`（浏览器临时目录）。

对方解压、双击启动、在页面上填自己的 SESSDATA，就是一套独立的东西。
两边数据完全不相干。

## 重新建库

关注列表变了，或者改了分类规则：

```
python bootstrap.py     # 拉关注 -> 补分区 -> 抓排行 -> 重新分类，一条龙
python probe.py         # 给一条视频都没有的人补一页投稿（可跳过）
python launch.py        # 启动
```

第一次用其实不用管：连上账号、第一次同步结束后它会自己跑一遍这条流水线，
跑完侧栏的分类才出来。想把四步拆开调，也可以单独跑：

```
python follow.py       # 重新拉关注
python enrich.py       # 补分区（只补新的）
python rank.py         # 抓推荐池
python probe.py        # 给空库的 UP 补一页投稿（可选，但分类会准很多）
python classify.py     # 重新分类
```

日常不用这么麻烦——应用里点「更新订阅」就行，它只翻动态流做增量。
